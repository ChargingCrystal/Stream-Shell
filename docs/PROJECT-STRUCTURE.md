# Stream Shell – project structure contract

This is an **unpacked Opera GX / Chromium MV3 extension**, not a Node/npm application. The extension root must contain `manifest.json` and `background.js`. Some scripts are deliberately generated by concatenating ordered source fragments; editing only the generated output makes the next build overwrite the change.

## Folder map

| Path | Owns | Rule |
| --- | --- | --- |
| `manifest.json`, `background.js` | MV3 entrypoints | Keep at repository/extension root; `background.js` is generated |
| `background/src/`, `background/tests/` | Browser windows, cross-surface state, transitions, Native Messaging, background tests | Edit `src/`, build using `background/build-background.ps1` |
| `common/src/`, `common/tests/`, `common/shell.js` | Shared content-script bootstrap, playback controls, resource governor | `common/shell.js` is generated |
| `dashboard/src/`, `dashboard/tests/`, `dashboard/` | Wide Dashboard, Settings, Compact Home wrapper, page CSS/HTML | Keep page entrypoints local; generated `dashboard.js` and `compact-home.js` |
| `landing/src/`, `landing/tests/`, `landing/` | Wide landing page, library/navigation, Finance UI and CSS | Generated `landing.js` **includes COBOL Finance**; Compact Home intentionally does not |
| `providers/` | Provider-specific adapters/themes and player integrations | No moving adapters into generic common code solely for cosmetic consistency |
| `twitch-workspace/` | Standalone Twitch slot page/controller | Keep its HTML/CSS/JS together; do not collapse into background worker |
| `native/titlebar-src/`, `native/tests/`, `native/` | C# partial-class modules, protocol and Windows installers; independent Discord helper | Helper compilation uses explicit partial assembly; no reordering casually |
| `integrations/cobol-finance/`, `integrations/unified-remote/` | Optional external/native integrations | COBOL report intentionally specialized, not a generic dashboard widget |
| `shared/`, `media/`, `subscriptions/` | Browser-agnostic registry/resume helpers, shared media API and subscription scraper | Preserve manifest/script paths; relocate only with all consumers updated |
| `offscreen/`, `popup/` | MV3 offscreen pages, audio utility and popup UI | Keep runtime entrypoints beside their HTML and tests inside `tests/` |
| `assets/` | Built-in artwork and user-supplied backgrounds | **Never bundle/overwrite local `assets/backgrounds/*.png` or custom user artwork** |
| `tools/` | Repository-wide validators and support tooling | Do not put features or runtime imports here |
| `.github/` | GitHub templates and CI workflows | CI checks the same project contracts as local developers |
| `docs/` | Long-lived developer notes, code audits, CI instructions, ruled-out ideas | Avoid adding unrelated prose into extension root |
| `release-notes/` | Historical version-by-version record | Keep filenames/URLs stable; no runtime imports from here |

## Root policy

The **root is not a generic place for new modules**. It retains only the extension's required entrypoints and conventional public project files (`README`, `CHANGELOG`, `LICENSE`, `CONTRIBUTING`, `SECURITY`, `NOTICE`, `.git*`). Future docs belong in `docs/`; changelog history stays in `release-notes/`. New areas require a clear owner and actual runtime/build reason, not simply a new feature name.

## Testing & builds

- Tests live in the owning component's `tests/` folder (`landing/tests/`, `offscreen/tests/`, etc.). Node discovers all `*.test.js` and CI requires several named regression contracts.
- Source is authoritative: four PowerShell builders emit the five shipped bundles, and `node tools/check-project.mjs` verifies **byte-for-byte** parity, manifest/HTML references, JS syntax, tests, native source contract and this directory layout.
- `native/tests/compile-titlebar-host.ps1` is exercised by the separate Windows GitHub Actions workflow; it is **not** part of the normal Linux JS test job.
- `assets/backgrounds/*.png`, user custom artwork and local diagnostics are deliberately excluded from shared patch/full releases. Never delete existing local wallpapers when applying a code patch.
- If a PR moves a runtime file, update `manifest.json`, all relative paths, every builder and `tools/check-project.mjs`; otherwise **do not** move runtime files just to make the tree look symmetrical.

## Safe layout-maintenance workflow

1. Make only file-placement / developer-tool changes in a structure release; do not mix Win32, Focus, Twitch, or renderer logic edits.
2. Update all inbound paths and moved tests' `__dirname` use.
3. Run `node tools/check-project.mjs`; CI should reject stray root files/tests and stale bundles.
4. Keep release patches compatible with existing installations: moving/deleting files requires explicitly removing the old paths from existing working copies. ZIP extraction alone never deletes them.
5. The live Windows Opera GX / C# runtime still needs real integration testing for behavior changes; a green CI check does not replace it.
