ARCHITECTURE GUARDRAILS
-----------------------
- Async IPC that expects a response must complete on success AND error, while retaining
  the message's existing payload format and sender authorization. Prefer the tested
  streamShellRespondAsync helper on suitable non-hot paths. Do not force it onto
  synchronous Runtime Diagnostics or fire-and-forget commands.
- No blanket timeouts, listener rewrites, or logging of expected background failures;
  any change to expensive Deep Diagnostics or Native/Twitch transitions needs separate
  latency budgets and behavioral tests.
- Shared Home/media data stays single-source. Do not fork separate Compact copies of Watchlist/Search/Continue/Recent/Direct/Subscriptions logic.
- Provider-specific DOM/player behavior belongs behind the dedicated provider adapters.
- Provider factories may override media snapshots (YouTube cache), but should not
  copy generic getCapabilities getters; the core binds them to the resolved adapter.
  Provider-owned media links must be validated and failed requests always answered.
- Provider API surface grows only for real shared-shell consumers.
- Netflix playback writes must use the MAIN-world bridge / Netflix player API; do not fall back to direct video.currentTime/play()/pause()/rate/volume mutations.
- Keep provider windows warm/minimized for fast switching; do not auto-close/reload inactive providers as a resource strategy.
- Native titlebar trust comes from explicit extension intent/claims. Native geometry, process, focus or taskbar observations may validate/reconcile a claim but must not independently promote normal Opera windows into Stream Shell.
- Unknown display layouts may receive a best-effort fallback, but they are not support targets.
